# warehouse-bot

An agent-ready ROS 2 + Gazebo robotics project, generated by
[Robotbase](https://github.com/tomnewtoneng/robotbase). Everything runs headless in Docker;
add `--gui` to any run to watch it in Foxglove.

This is the **arm** template: a fixed-base **2-DOF arm** (shoulder + elbow) with joint
position control — a starting point for manipulation tasks. It's a different robot class from
the mobile templates, exercising joint-space control instead of driving.

## Quickstart

```bash
robotbase up                                # start the container + build the workspace
robotbase test --list                       # see the scenarios
robotbase test reach-configuration --gui    # run one and watch it
```

The starter controller never commands the joints, so `reach-configuration` fails (the arm
just holds/droops). Your job is to make it pass.

## Where things are

- `src/warehouse_bot/warehouse_bot/controller.py` — **the controller you edit.**
- `src/warehouse_bot_description/` — the arm (URDF) and the world.
- `simulation/scenarios/` — the tasks to satisfy (YAML).
- `robotbase.yaml` — the project manifest (`fixed_base: true`, `ready_topics: [/joint_states]`).
- `AGENTS.md` — instructions for a coding agent.

## The loop

1. `robotbase test <scenario>` — runs it and prints a structured result (exit 0 = pass).
2. Read the `joint_positions` metric and the failed assertions.
3. Command the joints (publish `std_msgs/Float64` targets on `/shoulder_cmd` and
   `/elbow_cmd`) so the arm reaches the target configuration.
4. Rerun until it passes.

## Commands

Run `robotbase help` for the full list. Common ones: `up`, `test`, `episode summary`,
`launch --gui`, `stop`, `down`.
