# warehouse-bot

An agent-ready ROS 2 + Gazebo robotics project, generated by
[Robotbase](https://github.com/tomnewtoneng/robotbase). Everything runs headless in Docker;
add `--gui` to any run to watch it in Foxglove.

This is the **drone** template: a **quadrotor** flown by kinematic velocity control — a
different (aerial) robot class from the ground robots and the arm. Fly it with a 3D
`/cmd_vel` and read its pose (including altitude) from `/odom`.

## Quickstart

```bash
robotbase up                                # compile the specs, build, and boot the sim
robotbase test take-off                     # runs the scenario; prints a structured result
```

Out of the box this is a **minimal working drone**: the starter controller flies to (0, 0, 1.5)
and hovers, passing `take-off`. It's a starting point — replace it to fly to your own target
(read `/odom`, command 3-D `/cmd_vel`). A 3-D navigation challenge lives in the repo's
`examples/challenges/drone-navigate/`.

## Where things are

- `src/warehouse_bot/warehouse_bot/controller.py` — **the controller you edit.**
- `src/warehouse_bot_description/` — the drone (URDF) and the world.
- `simulation/scenarios/` — the tasks to satisfy (YAML).
- `robotbase.yaml` — the manifest (`ready_topics: [/odom]`, 3D `/cmd_vel` control).
- `AGENTS.md` — instructions for a coding agent.

## The loop

1. `robotbase test <scenario>` — runs it and prints a structured result (exit 0 = pass).
2. Read `final_x/y/z` and the assertion; `robotbase diagnose` explains a failure.
3. Publish a 3D `/cmd_vel` toward the target using `/odom` feedback (climb with `linear.z`).
4. Rerun until it passes.

## Commands

Run `robotbase help` for the full list. Common ones: `up`, `describe`, `test`, `diagnose`,
`episode summary`, `launch --gui`, `stop`, `down`.
